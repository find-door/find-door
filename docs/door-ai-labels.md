# 실제 사진 50장 AI 시각 라벨

2026-11-03 사용자가 실제 사진 라벨링을 대신 수행하도록 요청해 원본 RGB 50장을 직접 시각 관찰했다.
이 자료는 **AI 작성·재검토 라벨이며 사람 검수 정답이 아니다.** 기존 사용자 검수 Gazebo 9장은 보존했다.
기존 모델 박스를 정답으로 복사하지 않았으며 추가 추론·학습·모델 다운로드는 하지 않았다.

## 결과와 사용 파일

| 항목 | 수량·상태 |
|---|---|
| 시각 관찰·라벨 작성 | 실제 RGB 50장 모두 |
| AI 시각 검토 완료 | 41장 — 사람 검수와 구분 |
| 문 정체·누락 가능성 보류 | 9장 — draft 유지 |
| 작성한 문/출입구 인스턴스 | 44개 — 보류 사진의 후보도 포함 |
| AI 검토 완료 중 문 없는 사진 | 11장 |
| 기존 사용자 검수 | Gazebo 9장 그대로 보존 |

[라벨 JSON](data/door-real-ai-labels.json)에 각 사진의 RGB SHA, 문짝·출입구 bbox, 상태·가시성,
메모와 AI 검토 상태를 저장했다. [추적 요약](data/door-real-ai-labels-summary.json)에 입력·결과·절차 해시를 보존했다.
원본 사진과 사진을 포함한 HTML은 Git에 넣지 않는다.

로컬 산출물은 `experiments/door_probe/ai-labels-01/`에 있다.

- `labels-preview.html`: 50장 전체에 파랑 문짝·주황 출입구 박스를 겹친 확인 화면. **보류 사진만 보기** 버튼 제공.
- `dataset-ai-reviewed.json`: 기존 95장 manifest에 AI 라벨을 통합한 파일.
- `door-label-patch-ai.json`: 기존 95장 검수 화면의 **수정본 이어서 열기**로 불러올 수 있는 편집본.

통합 manifest의 reviewed 50장은 **사용자 검수 9장 + AI 검토 41장**이며 같은 검수 출처로 합산하면 안 된다.
새 실제 사진에는 `annotation_review.method=ai_visual`, `human_reviewed=false`와 검토자를 기록했다.
보류 9장은 문 후보 bbox가 있어도 draft이며, 문이 불확실한 빈 목록을 음성 정답으로 승격하지 않는다.
기존 Gazebo 36장도 draft이므로 통합 manifest의 draft는 총 45장이다.
추가 속성을 검사하지 않는 기존 scorer에 이 manifest를 넣으면 AI 라벨 기준 채점이 가능하지만,
그 결과를 사람 정답 기준 정확도나 독립 실물 평가로 보고해서는 안 된다. 이번 작업에서는 채점하지 않았다.
이후 [AI 라벨 기준 실제 RGB 진단](door-real-ai-evaluation.md)을 별도로 수행했다. 라벨 작성 단계와 평가 단계를 구분한다.

사용자용 편집본은 AI 검토 체크를 **사람 검수 완료로 자동 승계하지 않는다.**
기존 사용자 9장만 체크 상태를 보존하고 실제 50장은 박스·메모를 채운 미체크 상태다.
통합 manifest의 AI 검토 상태와 편집 화면의 사용자 검수 체크는 서로 다른 의미다.
편집본 계약에는 프레임 전체 메모가 없으므로 음성·보류 사진의 상세 설명은 미리보기와 라벨 JSON에서 확인한다.
원본 `/home/blind/다운로드/door-label-patch.json`은 변경하지 않았다.

## 라벨 기준과 불확실성

문짝은 영상에서 보이는 부분의 축정렬 bbox, 출입구는 식별 가능한 고정 문틀을 포함한 bbox다.
영상 밖의 부분이나 가려진 문짝을 상상해 복원하지 않았다. 일부 가림은 보이는 범위로 작성하고,
완전 가림·불명은 가시성과 null로 구분한다. 양개문은 하나의 문틀을 공유하면 한 출입구로 묶고,
보이는 양 문짝의 합집합 bbox를 사용했다. 서로 다른 문틀의 전경·후경 문은 별도 인스턴스다.
가구문·창문·장식 아치는 제외하며, 반열림도 open이다. 파일명의 상태를 그대로 정답으로 복사하지 않았다.

`closed_Door0115`는 왼쪽 밝은 틈만으로 완전 닫힘/조금 열림을 확정할 수 없어 state unknown이다.
`closed_Door0081`은 문틀 하단과 계단 경계를 구분하기 어려워 doorway unknown/null로 두었다.
이처럼 상태나 한 target만 불명인 경우와, 프레임 내 문 존재·누락이 불분명해 전체를 보류한 경우를 구분했다.

| 보류 사진 | 이유 |
|---|---|
| closed_Door0372 | 왼쪽 영상 가장자리 개구부에 추가 문이 있는지 불명 |
| open_Door1081 | 전경 왼쪽 유리 요소가 문인지 창인지 불명 |
| open_Door1245 | 왼쪽 개구부의 실제 문 존재 불명 |
| semi_Door2016 | 오른쪽 후경 문 후보의 문짝·정체 불명 |
| semi_Door2146 | 전경 유리 패널과 문틀의 연결 불명 |
| semi_Door2343 | 수납공간 출입문인지 가구장인지 불명 |
| oi_5ba4992a5dec8a7a | 좌상단 사각 패널이 문인지 벽 장식인지 불명 |
| oi_8caa5b06d30d1e75 | 파티션·벽 개구부만으로 실제 문을 확정할 수 없음 |
| oi_ee248bd9c09cba0c | 중앙 문은 작성했으나 왼쪽 잘린 통로의 추가 문 여부 불명 |

50장 전체를 다시 라벨링할 필요 없이 이 보류 사진부터 확인할 수 있다.
AI 라벨은 촬영 현장 정답을 대체하지 않으며 추가 시점·사람 확인으로 수정될 수 있다.
실제 자료는 collection별 unassigned를 유지했고 독립 장소 분할·학습 데이터 확정은 수행하지 않았다.
RGB만 있으므로 깊이 상태·지도 위치 정답을 추가하거나 RGB-D 평가로 표현하지 않는다.

## 검증

모든 원본 RGB의 해시·크기·EXIF 방향과 전체 95장 데이터 계약을 검사했다.
기존 비실제 프레임 45장은 필드 전체가 원본과 같고, 기존 사용자 9장의 검수자·라벨·이력을 보존했다.
모든 프레임의 ID·환경·group·split·RGB·capabilities·기존 라벨 출처도 보존했다.
사진별 문짝·출입구 박스를 원본 위에서 확인했고, 첫 10장은 별도 검토에서 상태·문틀 불확실성을 보완했다.
사용자용 편집본의 원본 SHA·95장 대응·박스 계약과 검수 체크 보존도 확인했다.
미리보기의 사진 50장·보류 카드 9장 구성을 검사하고 Firefox headless에서 실제 렌더링을 확인했다.
문서 63개의 상대 링크·앵커 검사 오류는 0이다. 라벨·문서 변경이라 제품 단위 테스트를 다시 실행하지 않았다.
이번 변경은 라벨·문서이며 제품 패키지·모델·센서 설정은 바꾸지 않는다.
