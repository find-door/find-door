# 문 상태 시간 종합과 저장 메모리

현재 단계는 **호출자가 제공한 고정 출입구 위치**에 상태 관측을 연결하는 순수 모듈이다.
출입구를 영상에서 찾거나 LiDAR 지도 좌표로 추정하는 기능은 아직 연결하지 않았다.
정답 위치를 제공하는 진단 결과를 지도 위치 추정 성능으로 보고하지 않는다.

## 동작 계약

`mapping_semantic.door_map.DoorMap`은 명시한 map_id·frame에 대해 다음을 수행한다.

- 관측 위치 0.25m 이내의 가까운 문을 연결한다. 두 후보의 거리 차이가 0.05m 미만이면
  임의로 하나를 선택하지 않고 모호한 연결로 거부한다.
- 문 위치는 최초 관측을 기준점으로 유지한다. 상태가 바뀌어도 ID와 위치는 그대로다.
  이는 첫 위치가 정확하다는 보장이 아니며 관측 위치 오차·드리프트 보정은 별도 문제다.
- 서로 다른 시각의 동일 상태 3회 연속 관측으로 closed/open을 확정한다.
  반대 상태나 unknown을 받으면 기존 확정 상태를 unknown으로 내리고 새 근거를 기다린다.
- 같은 문·같은 시각은 증거 횟수를 늘리지 않는다. 역행 시각은 거부한다.
- 마지막 관측부터 2초를 넘으면 상태를 unknown으로 표시한다. 긴 공백 뒤 새 관측은
  이전 연속 관측 횟수를 이어받지 않는다.
- 지도 초기화는 문 목록을 비우되 같은 인스턴스의 ID 번호를 재사용하지 않는다.

기본 연속 횟수·거리·TTL은 후보 설정이며 독립 자료에서 채택 검증한 수치가 아니다.
호출자는 문짝의 보이는 표면점이 아닌 고정 문턱 위치 추정치를 전달해야 한다.
관측 중단 때도 현재 시각으로 snapshot을 갱신해야 만료가 출력에 반영된다.

JSON 저장은 map_id·frame·설정·고정 위치·ID·관측 시각을 보존한다.
복원은 숫자·ID·시각·설정 호환성을 검증한 뒤 원자적으로 적용한다.
복원한 상태도 현재 시각에 따라 만료되며 이전 연속 투표 이력은 새 근거로 재사용하지 않는다.
이 모듈의 JSON은 개발 계약이며 ROS 문 지도 저장 서비스는 후속 구현이다.
온라인 SLAM 보정 감지와 reset 호출도 아직 자동으로 연결하지 않았다.

## 저장된 RGB-D를 이용한 통합 진단

[memory_check.py](../scripts/door_probe/memory_check.py)는 기존 2m 정면의 실제 Gazebo 깊이 기록을
닫힘 3장→열림 3장→닫힘 3장 순서로 연결한다. 관측 간격은 인위적으로 0.5초를 부여한다.
깊이 상태 후보의 출입구 ROI와 문 위치 `(0,0,0)`은 정답 입력이다.
이는 실제로 움직이는 문을 촬영한 상태 전이 시험이 아니다.

```bash
OPENBLAS_NUM_THREADS=1 /usr/bin/python3 scripts/door_probe/memory_check.py \
  --captures experiments/door_probe/run-01 \
  --output experiments/door_probe/memory-new
```

실행기는 기존 출력 폴더를 거부하고 원본 깊이 해시와 사용한 두 모듈의 해시를 남긴다.
고정 ID·위치, 세 관측 후 상태 전환, 전이 중 unknown, JSON 복원 및 만료를 검사한다.
실행 결과와 검증 상태는 아래 기록한다.

## 확인 상태

2026-11-02 메모리 단위 검사 28개와 저장 깊이 기록을 사용한 통합 진단을 통과했다.
원문은 로컬 `experiments/door_probe/memory-dev-03/check.json` 및 `doors.json`에 보존한다.
세 구간의 상태는 각각 unknown→unknown→closed, unknown→unknown→open,
unknown→unknown→closed였다. 전체 구간의 ID는 `door_000001`, 위치는 `(0,0,0)`으로 유지됐다.
복원 직후 closed, 관측 만료 후 unknown을 확인했다.
입력 위치는 정답이며 전체 영상에서 위치를 추정한 결과가 아니다.

관측과 snapshot의 시각은 단조 증가해야 한다. snapshot이 시각 watermark를 진행시키므로
그보다 늦게 도착한 과거 시각 관측은 거부된다. 실제 ROS 연결에서는 관측 정렬·대기 정책이 필요하다.

ROS 관측·마커·저장 서비스, 온라인 지도 보정 처리, 실제 상태 전이 촬영,
독립 장면·실물 평가는 여전히 필요하다.
