# ADR-0004: 로봇 도착 전 2D SLAM 기준선 유지

- **상태:** ✅ 결정 — 시뮬레이션·개발 기준선, 실물 최종 선정은 유보
- **날짜:** 2026-10-25
- **관련 단계:** Phase 1

## 배경

동일 기록 입력으로 실행 가능한 SLAM을 비교하고, 로봇 도착 뒤 센서 오차를 검증할
기준선을 정해야 합니다. Gazebo pose odom은 실제 휠 미끄러짐을 재현하지 않습니다.

## 선택지와 비교

| 항목 | slam_toolbox | Cartographer | Hector |
|---|---|---|---|
| 로컬 Humble 실행 | 실행·재생·지도 저장 확인 | 선택 의존성으로 실행·재생 확인 | 로컬 Humble 패키지 후보 미확인 |
| 같은 bag 3회 벽 RMSE | 2.29 cm | 2.51 cm | 실행 비교 안 함 |
| 같은 bag 3회 벽 P95 | 3.44 cm | 2.50 cm | 실행 비교 안 함 |
| 같은 bag coverage (10cm) | 100% | 98.45% | 실행 비교 안 함 |
| 입력 구성 | scan + odom TF | scan + odom 메시지·TF, IMU 사용 안 함 | ROS 2 유지보수 경로 추가 확인 필요 |

각 알고리즘의 3회 결과는 표의 반올림 정밀도에서 같았습니다. 픽셀 지도와 모든 원시
지표가 동일하다는 뜻은 아닙니다. 독립적인 환경 3개를
시험한 것이 아니며 통계적 우열·실물 실패율을 추정하지 않습니다.

## 결정과 이유

기본 launch는 이미 주행·저장·재생 도구와 연결한 slam_toolbox로 유지합니다.
Cartographer는 선택 비교 launch로 제공합니다. 이 bag에서 두 후보 모두 임시 품질 기준을
만족하고 단일 지표가 일관된 우열을 주지 않아, 한 지표만으로 기본 구현을 바꾸지 않습니다.
Hector는 실행 가능한 ROS 2 배포·유지보수 근거를 확인한 뒤 후보 포함을 재검토합니다.

## 포기한 것 / 위험

최초 온라인 예비 실행의 3.566m 급변 원인은 미확정입니다. replay 입력은 기록 시작 전
초기 scan 전체를 포함하지 않아 온라인 내부 상태 전체를 복제하지 못합니다.
루프 클로저를 끄는 것을 해결책으로 채택하지 않습니다. 실제 센서·오도메트리·CPU 부하와
다른 구조에서 비교한 뒤 실물 선정 결정을 갱신해야 합니다.

## 검증 방법

[동일 입력 재생 결과](../replay-evaluation.md)와 [루프 조사](../loop-closure-investigation.md)를
기준으로 코드·설정·원본 입력·고정 초기 정합을 보존합니다. 실물에서는
[인수 절차](../robot-acceptance.md)의 독립 정답과 성능 측정을 추가합니다.

## 2026-10-27 루프 후보 기준 변경

**기본 `slam.yaml`에 `use_scan_barycenter: false`를 넣습니다.** 루프 후보 거리를 scan 무게중심이 아니라
로봇 위치로 잽니다. 루프 클로저는 계속 켭니다.

- 원인: v2 실패는 무게중심 기반 후보 선택이 벽 너머 Room B scan을 후보로 넣어 생긴 3.67 m 오연결입니다
  ([원인 분석](../loop-closure-investigation.md#2026-10-26-원인-분석-스캔-무게중심-기반-루프-후보-선택)).
- 근거: 실패 bag 재생 P95 391.30 → 2.96 cm, 정상 bag 4개 회귀 재생 모두 통과(원래 설정이 재생에서
  실패한 1개 포함), 온라인 5회 모두 통과(P95 3.02–7.16 cm, 루프 최적화 9–10회).
- 다른 후보와 비교: `loop_search_maximum_distance: 2.5`는 무게중심 거리 2.94 m 대비 여유가 작고,
  `loop_search_space_dimension: 4.0`은 2 m를 넘는 실제 누적 오차 보정도 막으며,
  `loop_match_minimum_response_fine: 0.6`은 여유를 측정하지 않았습니다. 셋 다 같은 결함 주변의 여유만
  늘리므로, 원인을 직접 없애는 무게중심 해제를 택했습니다.
- 한계: 한 world·재생 bag 5개·온라인 5회 근거입니다. 과거 예비 실패(3.566 m)와 같은 원인인지 🔍.
  실물에서는 LiDAR 범위·문 구조가 달라 다시 확인합니다.
- 실물 첫 시험 프로파일의 `do_loop_closing: false`는 이 결정으로 바꾸지 않습니다 (아래 절, 실물 검증 전).
- 2026-10-31 갱신: 이 기본값도 `indoor_v2`에서 5회 모두 실패했습니다([재검증](../loop-closure-investigation.md#2026-10-31-indoor_v2-재검증)). `indoor_v1`의 결함을 없앤 결정으로는 유효하지만, 잘못된 루프 연결 전반을 막는 근거는 아닙니다. 기본값 변경은 원인 확인 뒤 판단합니다.
- 2026-11-01 갱신: 후보 3개가 큰 실패는 막았지만 미리 정한 품질 기준을 두 world에서 통과하지 못해 기본값을 유지합니다([후보 검증](../loop-closure-investigation.md#2026-11-01-indoor_v2-실패-후보와-설정-검증)). `indoor_v2`에서는 현재 기본값이 후보보다 훨씬 나쁘다는 점을 알고 내린 결정이며, 위치 오차 누적 조사 뒤 다시 판단합니다.
- 2026-11-01 정정: `slam.yaml`은 비교 기준이며 권장 설정이 아닙니다. 위 기본값 유지는 채택 근거가 없다는 뜻이고, 실물 기본값은 미선정입니다. 벽 너머 연결은 오연결 후보로 낮췄고, 처리 간격 0.5도 관측된 보정이 없어 채택하지 않았습니다.

## 첫 실물 시험 준비 보완

새 시작 전 기록의 같은 bag ON/OFF 각 3회에서는 ON만 P95 391.30cm로 실패하고 OFF는 6.63cm였습니다. [실행과 한계](../robot-readiness-evaluation.md)를 보존했습니다. 개발 기본 설정은 유지하되 첫 실물 프로파일은 loop OFF로 제한합니다. 이는 고장 원인을 확정하거나 일반적인 해결책·최종 실물 SLAM으로 채택하는 결정이 아니며, 인수 후 반복·독립 정답으로 재평가합니다.
