# ADR-0013: 검수 bbox의 문짝·출입구 기준별 검출 진단

- **상태:** ✅ 결정 — 평가 도구 계약, 실제 성능·학습 채택과 구분
- **날짜:** 2026-11-03
- **관련 단계:** Find Door 라벨 검수 이후 검출 학습 필요성 판단

## 배경

기존 첫 실험은 문틀 기하 bbox에 원 검출을 대응했다. 검출은 문짝을 감싸는 경우가 있어
두 기준을 섞으면 검출 누락과 박스 의미 차이를 구분하기 어렵다.
검수 중인 자료를 정답으로 채점하거나 실행 오류·미실행을 분모에서 빼는 것도 막아야 한다.

## 선택지와 비교

| 선택 | 장점 | 한계 |
|---|---|---|
| 기존 문틀 기준만 유지 | 과거 결과와 연결 | 문짝 검출과 출입구 기하 의미 혼재 |
| 두 정답 기준을 각각 평가 | 같은 검출 박스의 의미 차이 확인 | 대상별 유효 프레임 분모가 달라질 수 있음 |
| 두 기준을 합산 | 단일 점수 | 서로 다른 정답을 섞어 해석 곤란 |

## 결정과 이유

한 보고서에서 environment와 split을 각각 하나 명시한다. Gazebo·실제 RGB·실제 RGB-D를 합산하지 않는다.
reviewed 선언을 갖고 해당 target의 모든 문이 visible인 프레임만 그 target에서 채점한다.
어느 문의 target이 occluded/unknown이면 그 target의 프레임 전체를 제외 사유와 함께 기록한다.
ignore 영역 bbox가 없어 다른 검출의 FP 여부를 판정하기 어렵기 때문이다.
문 없는 reviewed 프레임은 검수한 음성으로 평가하며, draft는 항상 제외한다.
검수 선언의 진위와 빠진 문은 도구가 증명하지 않는다.

원 검출 door 박스를 leaf_bbox와 doorway_bbox에 각각 대응한다. IoU≥0.5 간선의 최대 개수 일대일 대응을 사용한다.
중복 박스는 추가 FP다. 대응 탐색은 IoU 내림차순·입력 순서로 결정적이지만 IoU 합을 최적화하지는 않는다.
이 진단은 원 검출 박스의 두 정답 기준 비교이며 출입구 추정 모듈·상태·지도 성능이 아니다.
confidence는 검증하되 추가 필터링하지 않고 입력 검출 설정을 출처로 남긴다. AP/mAP는 산출하지 않는다.

프레임 exact 성공은 모든 GT 문을 대응하고 FP가 0일 때다. 실행 오류와 예측 누락도 유효 프레임 분모에 남아 실패다.
P/R/F1은 유효 추론만의 조건부 지표로 명명하며 전체 GT 수와 유효 추론 GT 수를 함께 제공한다.
실행 오류·미실행의 미관측 FP/FN을 0으로 채워 전체 P/R처럼 표현하지 않는다.
F1은 2TP/(2TP+FP+FN_valid)의 count 정의를 사용한다.
대응된 TP의 평균 IoU도 조건부 값으로 기록한다. 분모가 없으면 null이며 0% 성공·통과로 바꾸지 않는다.

## 포기한 것 / 위험

완전 검수·가시성에 따른 선택 편향이 남는다. 두 target의 분모가 다르면 직접 점수 차이를 개선율로 해석하지 않는다.
reviewed/split/group 선언만으로 실제 독립 장소·사람 검수·라벨 완전성을 보장하지 않는다.
입력 provenance는 작성자 기록이며, 기존 시점 원문을 준비할 때는 원문·RGB 해시를 실제 대조한다.
모델 추가 학습, 새 추론, 클래스 확장·깊이 상태 평가를 이 도구에 넣지 않는다.

## 검증 방법

[검수 bbox 평가 안내](../door-label-evaluation.md)에 입력·분모·실제 실행 상태를 기록한다.
다중 문 greedy 대응의 함정·중복 검출·음성 프레임·unknown 가시성·검수 전 자료·실행 오류·예측 누락·환경 분리와
라벨 수정 후 기존 예측 재사용·출처 해시·원본 크기·덮어쓰기 거부를 검사한다.
현재 실제 자료의 채점은 검수본을 받은 뒤 별도 실행하며, 초안에서는 수치 없이 검수 대기를 확인한다.
