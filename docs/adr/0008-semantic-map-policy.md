# ADR-0008: 정적 객체 지도와 보정 epoch 초기화

- **상태:** ✅ 결정 — 고정 지도 우선, 보정 재투영은 미구현
- **날짜:** 2026-10-25
- **관련 단계:** Phase 2

## 배경

서로 다른 관측의 객체를 병합하고 저장하려면 ID·지도 좌표·움직임·SLAM 보정 정책이
필요합니다. 온라인 SLAM이 지도 좌표를 바꾼 뒤 과거 좌표를 그대로 유지하면 지도에
잘못된 객체가 남을 수 있습니다.

## 선택지와 비교

| 정책 | 장점 | 제한 |
|---|---|---|
| 관측·키프레임 재투영 | pose graph 변화에 맞춰 과거 관측 보정 가능 | 그래프 연계·변형 정책 추가 구현 필요 |
| 고정 지도 위치 추정 | 지도 좌표가 고정되어 누적 해석이 단순 | 고정 지도 준비 필요 |
| 큰 보정에 지도 초기화 | 과거 좌표 오염을 제한하고 단순 검증 가능 | 객체 손실·재관측 필요, 작은 오차는 남음 |

## 결정과 이유

정밀 누적은 고정 지도 운용을 우선합니다. 현재 온라인 시험에서는 epoch 최초 map→odom과
비교해 이동 0.2m 또는 yaw 0.1rad를 넘으면 객체·대기 관측을 비우고 DELETEALL을 발행합니다.
카메라가 멈춰도 TF를 감시하고 시뮬 시간 역행도 초기화합니다. 동일 노드 인스턴스의
epoch 초기화에서는 ID 번호를 재사용하지 않습니다. 새 프로세스는 번호 1부터 시작하며
기존 지도와 ID 이력을 이어갈 때는 저장 파일을 로드해야 합니다.

같은 클래스의 0.25m 이내 관측을 병합하고 서로 다른 시각 3회 이상 관측해야 확정합니다.
외부 모드 기본 정적 클래스는 chair/cup/bottle입니다. person 등 동적 클래스는 ID 없는
관측만 발행하며 정적 지도·JSON에 넣지 않습니다. 이 분류는 대상이 움직이지 않는다는
운용 가정이며 실제 물체 운동 추정은 아닙니다.

JSON은 map_id·frame·mode·클래스 계약과 수치·정규형 ID·int32 범위를 확인합니다.
저장 파일 덮어쓰기를 거부하고 현재 보정과 호환되는 파일만 명시적 서비스로 로드합니다.
fixture schema 1과 외부 검출 schema 2를 구분합니다. 관측 score와 불확실성은 별개입니다.

## 포기한 것 / 위험

작은 보정은 재투영하지 않습니다. yaw 오차는 원점에서 먼 객체의 위치 오차를 키울 수 있어
이 임계값이 전체 공간의 오차 상한을 보장하지 않습니다. 정적 클래스로 둔 물체가 움직이면
새 객체나 오래된 좌표가 남을 수 있습니다. 사람 추적·정적 객체 만료·글로벌 재투영은 미구현입니다.
map_id는 사용자가 정확한 지도 자산·원점을 식별하도록 부여해야 합니다.

## 검증 방법

[시맨틱 검증](../semantic-evaluation.md)에서 이동 후 ID 유지, JSON 저장·덮어쓰기 거부,
새 프로세스 복원, person 저장 제외를 확인했습니다. 별도 ROS 시험에서 카메라를 끄고
0.3m 보정을 발행했을 때 epoch 1·빈 객체 목록이 되는 것을 확인했습니다.
