# ADR-0012: 검출로 확인한 출입구의 RGB-D 재관측

- **상태:** ✅ 결정 — 제한적 개발 구현, 일반 문 인식 성능 채택과 구분
- **날짜:** 2026-11-03
- **관련 단계:** Find Door 검출 누락 중 상태 갱신

## 배경

평판 금속문의 완전 열림에서 기존 YOLOE의 유효 door seed가 없었다.
기존 노드는 매 프레임 검출이 필요해 이미 알고 있는 출입구라도 새 깊이를 처리하지 못했다.
문이 열려 문짝이 보이지 않는 상황에서 위치 기억과 현재 상태 판단을 분리해야 한다.

## 선택지와 비교

| 선택 | 장점 | 위험·제약 |
|---|---|---|
| 매 프레임 문 검출 필수 | 의미 근거가 매번 있음 | 열린 문짝 검출 누락 시 기존 출입구도 갱신 중단 |
| 과거 상태·영상 ROI 그대로 재사용 | 간단함 | 낡은 상태 유지·카메라 이동 오투영 |
| 확인한 출입구 기하 재투영 + 현재 RGB-D 검증 | 문짝 누락 중 새 상태 근거 사용 | 기존 semantic 확인과 기하 일치 검사 필요 |
| 검출 없이 모든 문틀에서 새 문 생성 | 새로운 열린 문 발견 가능 | 창·장식·통로와 의미 구분 불충분, 이번 범위 밖 |

## 결정과 이유

정상 문 검출에서 연속 근거로 상태가 확정된 출입구만 임시 캐시에 보관한다.
추정 bbox의 네 광선과 추정 벽 평면 교점을 관측 시각 map←camera TF로 옮긴다.
무검출 RGB-D 묶음도 처리 큐로 넘기고, 현재 관측 시각 TF로 캐시를 영상에 재투영한다.
영상에 충분히 보이는 캐시가 정확히 하나일 때 그 영역을 출입구 추정 seed로 사용한다.
매번 현재 RGB·depth에서 양쪽 문틀·벽 평면·문턱·상태를 다시 구한다.
이전 상태·깊이·world 정답을 새 상태 근거로 사용하지 않는다.

현재 출입구의 anchor 거리≤0.1m, 벽 평면 잔차≤0.08m, 법선 각도≤10°,
폭 상대 차이≤20%일 때만 같은 문 ID를 갱신한다. 투영 bbox의 영상 내 면적 비율은 최소 50%다.
DoorMap.observe의 expected_id로 새 ID 생성·다른 기존 ID 연결도 거부한다.
판단 근거가 부족하면 갱신하지 않고 기존 TTL·unknown 정책을 따른다.
검출 없는 재관측으로 캐시 기하 자체를 갱신하지 않는다.

`reobserve_known_doors` bool 인자는 기본 true이며 doors/live_doors launch에서 노출한다.
false는 캐시 계산을 생략하는 기존 매 프레임 검출 필수 경로다.
정상 검출에서 캐시 네 점을 만들지 못해도 정상 관측은 유지하고 캐시만 제거한다. 카운터 reobserved는 현재 RGB-D 기반 재관측 처리 수다.
캐시는 세션 내에서만 유지하며 큰 지도 보정·시각 역행·성공한 load 때 비운다.
저장 JSON·토픽·메시지 타입은 유지한다. 복원 직후에는 검출 기반 확인으로 기하를 다시 확보해야 한다.

## 포기한 것 / 위험

처음 보는 완전히 열린 문의 검출은 해결하지 않는다. 기존 semantic 확인을 재사용하는 경로다.
양쪽 돌출 문틀·균일 벽·수평 카메라 등 기존 출입구 추정 가정이 유지된다.
캐시가 여러 개 보이면 무검출 재관측을 거부한다. 일반 다중 문 추적은 미완료다.
창·가림·비슷한 문틀에 대한 의미 혼동은 제한된 기하 일치 검사만으로 완전히 배제할 수 없다.
상수는 개발 후보이며 독립 실제 자료에서 검증하지 않았다.

## 검증 방법

[재관측 검증](../door-reobservation.md)에 단위·실제 ROS·Gazebo 결과를 기록한다.
무검출로 새 객체를 생성하지 않는지, 현재 깊이에 따른 상태 전환, 이동 카메라 재투영,
기하 불일치·관측 중단·epoch 초기화·load 후 캐시 제거를 검사한다.
금속문 반열림에서 확인한 뒤 완전 열림·닫힘으로 바꾸는 시험과 처음 열린 문의 검출 성능을 구분한다.
