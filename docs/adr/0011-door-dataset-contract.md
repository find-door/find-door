# ADR-0011: 문짝·출입구 이중 라벨과 장면 그룹 분할

- **상태:** ✅ 결정 — 개발 데이터 계약, 라벨 품질·학습 준비 완료와 구분
- **날짜:** 2026-11-03
- **관련 단계:** Find Door 자료·평가 준비

## 배경

첫 실험에서 검출은 열린 문짝을 감쌌고 정답은 고정 문틀을 포함해 같은 문이어도 IoU가 낮았다.
기존 자료의 문 bbox를 새 문짝 또는 출입구 정답으로 자동 재해석하면 성능 지표와 학습 대상이 바뀐다.
연속 영상·동일 장면 중복이 학습과 시험 양쪽에 들어가는 것도 막아야 한다.

## 선택지와 비교

| 계약 | 장점 | 한계 |
|---|---|---|
| 기존 door bbox 하나 | 기존 라벨 사용 가능 | 문짝과 고정 출입구 의미 혼재 |
| 문짝·출입구 bbox 분리 | 검출·고정 위치 입력을 별도로 평가 | 가시성·재검수 필요 |
| 인스턴스 마스크 | 세밀한 형상·가림 표현 | 현재 박스 파이프라인보다 라벨 비용 증가 |

## 결정과 이유

`schema_version=1` 개발 manifest에서 문 ID별 leaf_bbox와 doorway_bbox를 분리한다.
가시성은 visible/occluded/unknown이며 visible에는 영상 안의 bbox가 필요하다.
draft의 빠진 문 필드는 unknown/null로 채우고, reviewed에는 필드를 명시하도록 요구한다.
과거 라벨은 legacy_labels에 보존하며 새 bbox로 승격하지 않는다.

환경은 gazebo/real_rgb/real_rgbd로 구분하고 depth·CameraInfo·TF 제공 능력을 별도 선언한다.
같은 RGB 해시 중복과 같은 group_id의 split 혼합을 거부한다.
미할당 자료를 임의로 학습/시험에 나누지 않으며 Gazebo와 실제 자료의 그룹 혼합도 거부한다.

## 포기한 것 / 위험

검증기는 형식·수치·중복·선언된 그룹만 확인한다. 사람 검수 진위·빠진 문·실제 장소 동일성·보정 정확도는 증명하지 않는다.
group_id는 실제 문·장소·촬영 세션에 맞게 검수해야 한다.
reviewed라도 특정 bbox가 없으면 해당 대상의 양성 학습 라벨로 사용할 수 없다.
현재 인벤토리는 이중 bbox 검수가 끝나지 않아 전부 draft다.

## 검증 방법

[자료 준비·실제 사진 참고 감사](../door-dataset.md)에서 원본 해시·크기와 분모를 확인한다.
중복·그룹 누출·가시성과 bbox·환경 능력·잘못된 수치를 단위 검사한다.
기존 C 원문 재감사는 새 모델 추론·새 파이프라인의 실제 환경 평가와 구분한다.
