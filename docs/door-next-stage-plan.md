# 문 검출 이후 구현 계획

상태: 🚧 2026-11-02 후속 구현 승인 후 진행 중. 이 문서는 최종 알고리즘 채택 결정이 아니다.
깊이 후보 모듈과 [정답 ROI 개발 진단](door-state-evaluation.md)을 구현했다.
라벨·출입구 추정·시간 종합·지도 통합·실제 자료 평가는 남아 있다.
[첫 실험](door-experiment.md)의 결과와 지표는 유지한다.

## 첫 실험에서 확인한 문제

완전 열림 조건의 문틀 IoU 성공은 0/27이지만 18/27프레임에서 door 박스가 나왔다.
확인한 영상에서 검출은 회전한 문짝을 감쌌고, 정답은 고정 문틀과 빈 출입구를 포함했다.
따라서 문 검출 모델의 성능과 지도에 저장할 출입구 위치를 서로 다른 지표로 평가한다.
기존 카메라의 문 영상은 모두 상단이 잘렸으며, 조건별 세 프레임은 동일 RGB였다.
이 자료는 개발·회귀 자료로 사용하고 새로운 독립 시험셋으로 재명명하지 않는다.

## 구현할 입력과 출력

| 항목 | 제안 | 확인할 내용 |
|---|---|---|
| 문짝 검출 | 보이는 문짝의 bbox·score·RGB header | 문틀·장식 패널 중복과 구분 |
| 출입구 추정 | 문틀·벽 경계에서 고정된 문턱 중앙과 벽 방향 추정 | 문짝 표면이나 뒷벽의 점을 문 위치로 저장하지 않음 |
| 상태 판단 | 정렬 depth·CameraInfo·문 영역·주변 벽 평면으로 open/closed/unknown | 무효 깊이·가림·벽 평면 추정 실패 시 unknown |
| 시간 종합 | 같은 출입구의 관측 시각별 상태 근거·최종 갱신 시각 | 중복 영상으로 관측 횟수를 늘리지 않음 |
| 지도 | 고정 ID·map 좌표·상태·관측 시각·관측 근거 | 상태 변화가 문 위치나 ID를 바꾸지 않는지 확인 |

검출 연결은 기존 `vision_msgs/msg/Detection2DArray` 경계를 우선 사용한다.
문 상태를 class_id의 `door_open`/`door_closed`로 나누면 현재 클래스별 객체 병합에서
동일 문이 분리될 수 있으므로, 위치 식별과 상태 속성을 분리하는 저장 계약이 필요하다.
정확한 ROS 출력·JSON schema는 🔍 미정이며 구현 전에 기존 계약과 호환 범위를 검토한다.

## 권장 진행 순서

### 1. 라벨과 독립 시험 조건 준비

- 첫 실험은 문틀 기준으로 그대로 보존한다. 새 문짝 평가를 추가할 때는 별도 평가 이름과 정답 파일을 둔다.
- 보이는 문짝 bbox와 출입구 bbox를 별도 기록하고, 보이지 않는 문짝·문틀은 가시성 불명으로 표시한다.
  가려진 전체 문짝 영역을 임의로 복원해 검출 정답으로 사용하지 않는다.
- 상태 정답은 닫힘/열림/불명이다. Gazebo 배치 45°와 90°는 둘 다 열림이며 각도도 별도 보존한다.
- 시뮬레이터의 문 pose·모델 이름·배치 각도는 정답 생성과 평가에만 사용한다.
  상태 추론과 위치 추정 입력에 넣지 않는다. 위치를 정답으로 주는 시험은 별도 진단으로 표시한다.
- 개발·검증·시험은 프레임 무작위 분할 대신 문 모델·재질·공간·촬영 세션 단위로 나눈다.
  같은 정적 장면과 인접 영상 프레임이 양쪽에 섞이지 않게 그룹을 기록한다.
- 원래 로봇 시점을 유지한 시험과, 문 전체가 보이는 보조 카메라 시험은 별도 조건으로 관리한다.
  보조 카메라 설정은 🔍 미정이며 기존 오버레이를 변경하는 대신 별도 실험 설정을 검토한다.

완료 근거: 데이터 manifest·해시·가시성·분할 그룹·라벨 검수 기록과 장면 예시.
사람 검수 전 라벨은 초안으로 표시한다.

### 2. 깊이 기반 상태 후보의 오프라인 검증

먼저 주변 벽 픽셀을 3D로 역투영하고 벽 평면을 추정한다. 문 영역 깊이는 같은 영상 행의
단순 거리 차이 대신 벽 평면까지의 거리와 비교한다. 사선에서 평평한 벽 자체의 깊이가
달라지는 영향을 줄이기 위한 제안이며 성능은 아직 확인하지 않았다.

닫힌 문은 벽과 비슷한 평면에 있을 수 있고, 열린 문에서는 뒷벽 깊이와 기울어진 문짝이
함께 나타날 수 있다. 문짝 박스만 사용하면 열린 틈이 빠질 수 있으므로 출입구 ROI 추정이
함께 필요하다. 벽과 문의 오프셋, 가림·유리·깊이 결손도 개발 조건에 포함한다.
유효 깊이 비율·벽 평면 품질·판정 여유가 부족하면 unknown을 출력한다.
임계값은 개발 자료에서 정하고 시험 전에 고정한다.

시간 종합은 실제 시각 간격이 있는 관측을 사용한다. 정적 배치 세 장을 반복하는 시험과,
같은 문을 실제로 열고 닫으며 지연·전이·오래된 상태를 확인하는 시험을 구분한다.
관측 중단 시 이전 상태를 언제까지 유효하게 둘지는 🔍 미정이다.

완료 근거: 개발 설정, 고정 시험 설정, 상태 혼동행렬·unknown 비율·관측 전이 지연,
실패 사례 RGB/depth 그림. 정답 ROI를 제공한 진단 결과와 검출부터 실행한 전체 결과를 각각 보고한다.

### 3. 문 검출 학습 필요성과 범위 결정

첫 실험의 문틀 IoU 0만으로 문짝 검출 학습이 필요하다고 확정하지 않는다.
문짝 정답으로 기존 C를 평가한 뒤 누락·중복·시점 문제를 분석한다.
사용자가 제안한 YOLOv11 학습은 후보로 두고, 확보된 문 데이터와 실행 환경을 확인한 뒤
체크포인트·학습 대상·분할·평가 설정을 고정한다. 새 의존성·가중치 설치나 다운로드가
필요하면 구체적인 대상과 용량을 확인한다. 현재 설치된 YOLOE와 새 학습 모델은 구분한다.

완료 근거: 학습/검증/시험 manifest, 모델·설정 해시, 동일 시험셋의 기준선 대비 결과.
실제 영상과 Gazebo의 precision/recall·bbox 지표를 합산하지 않는다.

### 4. ROS와 시맨틱 지도 통합

RGB/depth/CameraInfo 동기화와 관측 시각 TF를 유지하고, 고정 지도에서 위치와 상태 연결을
먼저 검증한다. 기존 mapper의 기본 점수 기준 0.5와 C의 문 기준 0.1이 다르므로,
문 어댑터의 설정을 명시하고 단순 연결만으로 동작한다고 가정하지 않는다.

출입구 위치가 관측되지 않으면 문짝의 대표 표면점으로 대체하지 않는다.
문틀 추정 실패·동일 문 연결 실패는 별도 결과로 남긴다.
지도 보정 시 과거 문 위치와 상태를 어떻게 처리할지는
[현재 객체 정책](adr/0008-semantic-map-policy.md)과 함께 검토하고 설계 결정을 남긴다.

완료 근거: 동일 문 닫힘→열림→닫힘에서 ID와 고정 위치 유지, 지도 저장/복원,
TF 실패·시각 역행·지도 보정·관측 중단 처리, 실제 ROS 출력과 RViz 표시 확인.
GUI 확인은 사용자 요청 범위에서 수행한다.

## 평가 표와 최종 완료 조건

| 평가 대상 | Gazebo | 실제 촬영 자료 |
|---|---|---|
| 문짝 검출 | 문짝 bbox 정답으로 TP/FP/FN·IoU | 독립 문/장소/세션의 별도 정답·분모 |
| 고정 출입구 위치 | world 정답과 map 위치 오차, 연결 실패율 | 실측 정답·카메라 보정·자세 정보가 있을 때 평가 |
| 문 상태 | 정답 open/closed 전체 기준 정확도, 예측 unknown·누락은 실패 | 실제 영상 정답으로 별도 혼동행렬·분모 |
| 시간 종합 | 상태 전이 지연·오래된 상태·ID 유지 | 실제 연속 영상에서 별도 평가 |

상태 정확도는 정답이 open/closed인 모든 문을 분모로 두며 검출된 문만으로 분모를 줄이지 않는다.
정답 자체가 unknown인 문은 이 정확도 분모에서 제외하고 별도 개수·비율로 보고한다.
예측 unknown 비율과 관측 성공 여부도 함께 기록해 불명 출력 증가로 성능이 좋아 보이지 않게 한다.

RGB 영상만 있는 실제 자료로는 문 검출·상태 관찰을 평가할 수 있지만,
RGB-D 기반 상태 알고리즘이나 미터 단위 지도 위치를 검증했다고 표현하지 않는다.
실제 자료의 경로·RGB-D 유무·CameraInfo·관측 자세·정답 제공 범위는 🔍 미확인이다.
수치 채택 기준은 시험 전에 정하며, 기준 미달도 결과에 남긴다.

최종 목표는 지도 위 고정된 문 위치에 open/closed/unknown을 표시하고 저장·복원하며,
Gazebo와 실제 자료의 독립 평가·한계를 과목 보고서와 데모에 제시하는 것이다.
현재 이 완료 조건은 충족하지 않았다.
